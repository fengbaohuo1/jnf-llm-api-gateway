# 网关总体架构与请求链路

## 定位与运行形态

LLM API 网关是一个**本地个人工具**：桌面应用提供管理界面，同时内置一个本地 HTTP 服务作为 OpenAI 兼容入口。默认监听 `http://127.0.0.1:8787`，基础路径为 `/v1`。

客户端接入方式与官方 OpenAI 完全一致：把 Base URL 填成网关地址，把密钥填成网关签发的 `sk-llmapi-` 开头的接入密钥即可，客户端代码不需要任何改动。

## 一次完整请求的主链路

一次 `/v1/chat/completions` 请求会依次经过以下阶段：

1. **接入鉴权**：校验密钥是否存在、是否启用、是否过期、配额是否用尽。失败会记录到认证事件表（匿名失败也记录，用于暴力破解检测）。
2. **请求侧安全扫描**：扫描提示词与输入中的敏感信息（密钥、密码、手机号等）与注入特征，可脱敏后放行或直接拦截。
3. **渠道调度**：根据目标模型从启用的渠道中选出主渠道（详见《负载均衡与故障转移》）。
4. **上游透传**：把请求体原样转发给上游，只改写 URL 与鉴权头——不重建字段，因此 tools、思考参数等扩展字段都能保留。
5. **响应侧安全扫描**：对输出做同样的扫描与脱敏。
6. **记账落库**：解析用量明细，按单价计算成本，写请求日志并累加每日统计。

## 流式与非流式

流式请求走 SSE 透传：逐条转发上游事件，同时对增量内容脱敏。为了拿到精确的 token 统计，网关会尝试注入 `stream_options.include_usage` 参数；上游不支持时退化为本地估算（1 token 约等于 4 个 ASCII 字符或 1.5 个非 ASCII 字符）。

## 数据与配置

- 配置采用扁平键值文件 `settings.json`，文件是权威：启动时导入覆盖数据库，界面修改时双写回文件，也支持热重载。
- 运行时数据（渠道、密钥、日志、用量、审计）存本地 SQLite。
- 应用带系统托盘：关闭窗口默认隐藏到托盘继续提供服务；支持开机自启与单实例。

## 设计取舍

- **透传而非字段映射**：多协议入口接入后统一为 OpenAI 格式，转发层不感知业务字段，扩展性最好。
- **失败尝试也记账**：请求不因渠道失败而丢失记录——重试次数与失败原因都会写进日志，方便排查。
