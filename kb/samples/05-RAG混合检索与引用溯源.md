# RAG 混合检索与引用溯源

## 一句话定位

知识库模块负责"把自有文档变成可检索、可问答的知识资产"：导入文档后，支持关键词检索、向量语义检索、两者融合的混合检索，并支撑带引用溯源的问答对话。

## 文档入库流程

1. **解析**：Markdown 文档被解析成结构化的章节流，标题层级还原成溯源路径（如「第三章 / 3.2 节」）；纯文本整体作为一个无标题章节。代码块内的 `#` 不会误判成标题。
2. **分块**：先按章节切，超长章节再按空行段落贪心合并；只有单段超长时才使用重叠窗口硬切。默认分块 800 字符、重叠 150 字符（可配，上限 4000）。
3. **落库 + 双全文索引**：分块与文档在同一事务内写入，同时同步两张 FTS 索引——bigram 索引（把 CJK 连续段切成 2 字滑窗，承载中文检索）与 trigram 索引（content/heading/title 三列，服务英文子串匹配）。
4. **向量化**：送入 embedding 的文本是「标题 + 章节路径 + 正文」（存储与展示仍是原文），配方版本写入索引元数据；换配方后旧索引会被明确要求重建，避免同一库混用两套语义。
5. **去重**：同一知识库内按内容哈希拒绝重复导入。

## 三种检索模式

**关键词（keyword）**：BM25 打分，走两张索引。中文主力是 **bigram 索引**——写入时把 CJK 连续段切成 2 字滑窗（「网关怎么做」→「网关 关怎 怎么 么做」），查询侧同样切成 bigram 短语后 OR 连接，因此任意 ≥2 字符的查询都能命中（trigram 分词器天生匹配不了 3 字符以内的查询，这正是它做不了中文短词的原因）。**trigram 索引**只服务非 CJK 且 ≥3 字符的词元，用来补英文部分匹配（`embed` 能命中 `embedding`）。两路命中后用 RRF 融合。查询先按标点切段并剔除停用词；两条路都没有可用词元（例如单个字符）时才回退为带转义的 LIKE 子串扫描，防通配符注入。

**向量（vector）**：每个分块用 embedding 模型向量化（向量按 L2 归一化，相似度 = 1 − 距离 = 余弦相似度）。全部分块向量建成本地 HNSW 近似最近邻索引，查询时同样把问题向量化后在图里找最近邻居。维度必须与库绑定一致，索引状态机（未构建/构建中/就绪/失败）全程可见，可中断恢复。

**混合（hybrid）**：关键词与向量两路各取一批结果，用 RRF（Reciprocal Rank Fusion）融合：分块在每路结果的排名记为 rank，融合分 = Σ w/(60+rank)，其中向量路权重 1.0、关键词路 0.7，按分块去重后降序取前 K。两路都命中的分块天然排最前，且不需要归一化 BM25 与余弦这两种量纲。每条命中同时保留两路原始分（余弦相似度与 bm25），便于人工核查排序依据。

## 一致性守卫

向量索引的构建是快照式的：文档增删后未重建就检索会得到过期结果。因此检索前会校验当前分块数与索引记录的分块数，不一致时明确报错提示"请重新构建"，而不是静默返回陈旧数据。索引文件只是可重建的缓存，权威数据始终是分块表里的向量。

## 问答的自动策略

- 有可用向量索引：走混合检索，取回最相关分块；
- 没有 embedding 绑定或索引不可用：**自动降级为关键词检索**，问答仍然可用（只是召回从"语义相关"退化为"字面相关"）；
- 检索结果还要过一层策略：多取候选 → 确定性重排（两路皆中、标题/章节命中加分，同一文档最多保留 2 块）→ 相关度阈值（纯语义命中的相似度低于默认 0.45 就丢弃，该阈值按嵌入模型实测校准）→ 邻居扩展（把命中块的相邻分块并入引用上下文，引用编号仍指向原命中块）。

## 引用溯源

- 系统提示约束模型：只依据引用材料回答，出处用 [n] 标注；材料中没有的信息要明说"知识库中未找到相关信息"，不得编造；
- 引用上下文有预算（约 6000 字符），单块超长截断，防个别大块吞掉全部预算；
- 回答成功才落库：用户问题与模型回答（含引用 JSON、模型、token 数）成对写入会话；
- 界面上的 [n] 引用可一键跳转到对应分块原文核对。

## 边界与后续

明确不做（现阶段）：流式回答、reranker 模型（当前重排是零模型成本的确定性规则）、多轮记忆压缩。检索质量用评测集量化：用例文件给出「问题 → 期望文档」，跑出 recall@k、MRR 与拒答正确率，改动前后用同一份用例对比。会话历史保留最近几轮，更早的内容由引用上下文承载。
