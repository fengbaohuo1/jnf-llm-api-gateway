# RAG 混合检索与引用溯源

## 一句话定位

知识库模块负责"把自有文档变成可检索、可问答的知识资产"：导入文档后，支持关键词检索、向量语义检索、两者融合的混合检索，并支撑带引用溯源的问答对话。

## 文档入库流程

1. **解析**：Markdown 文档被解析成结构化的章节流，标题层级还原成溯源路径（如「第三章 / 3.2 节」）；纯文本整体作为一个无标题章节。代码块内的 `#` 不会误判成标题。
2. **分块**：先按章节切，超长章节再按空行段落贪心合并；只有单段超长时才使用重叠窗口硬切。默认分块 800 字符、重叠 150 字符（可配，上限 4000）。
3. **落库 + 全文索引**：分块与文档在同一事务内写入，同时同步到 FTS5 全文索引（trigram 分词，支持中文任意子串检索）。
4. **去重**：同一知识库内按内容哈希拒绝重复导入。

## 三种检索模式

**关键词（keyword）**：FTS5 BM25 打分。查询不足 3 个字符时 trigram 无法匹配，自动回退为带转义的 LIKE 子串扫描，防通配符注入。

**向量（vector）**：每个分块用 embedding 模型向量化（向量按 L2 归一化，相似度 = 1 − 距离 = 余弦相似度）。全部分块向量建成本地 HNSW 近似最近邻索引，查询时同样把问题向量化后在图里找最近邻居。维度必须与库绑定一致，索引状态机（未构建/构建中/就绪/失败）全程可见，可中断恢复。

**混合（hybrid）**：关键词与向量两路各取一批结果，用 RRF（Reciprocal Rank Fusion）融合：分块在每路结果的排名记为 rank，融合分 = Σ 1/(60+rank)，按分块去重后降序取前 K。两路都命中的分块天然排最前，且不需要归一化 BM25 与余弦这两种量纲。

## 一致性守卫

向量索引的构建是快照式的：文档增删后未重建就检索会得到过期结果。因此检索前会校验当前分块数与索引记录的分块数，不一致时明确报错提示"请重新构建"，而不是静默返回陈旧数据。索引文件只是可重建的缓存，权威数据始终是分块表里的向量。

## 问答的自动策略

- 有可用向量索引：走混合检索，取回最相关分块；
- 没有 embedding 绑定或索引不可用：**自动降级为关键词检索**，问答仍然可用（只是召回从"语义相关"退化为"字面相关"）。

## 引用溯源

- 系统提示约束模型：只依据引用材料回答，出处用 [n] 标注；材料中没有的信息要明说"知识库中未找到相关信息"，不得编造；
- 引用上下文有预算（约 6000 字符），单块超长截断，防个别大块吞掉全部预算；
- 回答成功才落库：用户问题与模型回答（含引用 JSON、模型、token 数）成对写入会话；
- 界面上的 [n] 引用可一键跳转到对应分块原文核对。

## 边界与后续

明确不做（现阶段）：流式回答、文档级过滤与重排序、多轮记忆压缩。会话历史保留最近几轮，更早的内容由引用上下文承载。
